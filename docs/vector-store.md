# Vector Store

## 벡터스토어 저장의 필요성

1.  빠른 검색 속도:
    - 임베딩 벡터들을 효과적으로 저장하고 색인화함으로써, 대량의 데이터 중에서도 관련된 정보를 빠르게 검색할 수 있습니다.
2.  스케일러빌리티:
    - 데이터가 지속적으로 증가함에 따라, 벡터스토어는 이를 수용할 수 있는 충분한 스케일러빌리티를 제공해야 합니다. 효율적인 저장 구조는 데이터베이스의 장성을 보장하며, 시스템의 성능 저하 없이 대규모 데이터를 관리할 수 있도록 합니다.
3.  의미 검색(Semantic Search) 지원:
    - 키워드 기반 검색이 아닌 사용자의 질문과 의미 상으로 유사한 단락을 조회해야하는데, 벡터스토어는 이러한 기능을 지원 합니다. 텍스트 자체가 저장되는 DB 의 경우 키워드 기반 검색에 의존해야 하는 한계성이 있지만, 벡터스토어는 의미적으로 유사한 단락 검색을 가능하게 합니다.

## 벡터스토어 중요성

벡터스토어 저장 단계는 RAG 시스템의 검색 기능 직접적으로 연결되어 있으며, 전체 시스템의 응답 시간과 정확성에 큰 영향을 미칩니다. 이 단계를 통해 데이터 가 잘 관리되고, 필요할 때 즉시 접근할 수 있도록 함으로써, 사용자에게 신속하고 정확한 정보를 제공할 수 있습니다.

## Vector DB

- Chroma

  - local DB 에서 사용하면 좋은 Vector DB
  - support 하는 기능이 다양함
  - 설명: Python 기반의 오픈소스 임베딩 데이터베이스로, 로컬 환경에서 쉽게 설정하고 사용할 수 있음
  - 장점: 설치가 간단하고, 메모리 내 저장소 옵션 제공, LangChain과의 통합이 원활함
  - 단점: 대규모 프로덕션 환경에서는 성능 제한이 있을 수 있으며, 분산 시스템 지원이 제한적임

- Faiss (Facebook AI Similarity Search)

  - 설명: Facebook AI Research에서 개발한 효율적인 유사성 검색 및 밀집 벡터 클러스터링 라이브러리
  - 장점: 대규모 데이터셋에서 매우 빠른 검색 성능, 다양한 인덱싱 방법 제공, 메모리 효율적인 구현
  - 단점: 주로 C++로 작성되어 Python 인터페이스가 제한적일 수 있으며, 영속성 기능이 내장되어 있지 않음

- Milvus

  - 설명: 대규모 벡터 검색을 위한 오픈소스 분산형 벡터 데이터베이스
  - 장점: 수십억 개의 벡터에 대한 확장성, 하이브리드 검색(벡터+스칼라) 지원, 강력한 클러스터링 기능
  - 단점: 설정 및 관리가 복잡할 수 있으며, 소규모 프로젝트에는 과도한 리소스가 필요할 수 있음

- Pinecone

  - 설명: 완전 관리형 벡터 데이터베이스 서비스로, 서버리스 아키텍처 제공
  - 장점: 인프라 관리 필요 없음, 높은 확장성, 낮은 지연 시간, 간단한 API
  - 단점: 클라우드 전용 서비스로 비용이 발생하며, 데이터 주권 문제가 있을 수 있음

- Weaviate

  - 설명: GraphQL 인터페이스를 갖춘 오픈소스 벡터 검색 엔진
  - 장점: 스키마 기반 접근 방식, 다중 모달 데이터 지원, GraphQL을 통한 직관적인 쿼리
  - 단점: 학습 곡선이 있으며, 다른 솔루션에 비해 커뮤니티가 상대적으로 작을 수 있음

- Qdrant
  - 설명: 벡터 유사성 검색 및 필터링을 위한 오픈소스 벡터 데이터베이스
  - 장점: 필터링 기능이 강력하고, REST API 및 gRPC 인터페이스 제공, 클라우드 및 온프레미스 배포 옵션
  - 단점: 다른 솔루션에 비해 상대적으로 새로운 기술이며, 특정 고급 기능이 아직 개발 중일 수 있음

## 벡터 DB 선정 기준

다음은 프로젝트에 적합한 벡터 DB를 선택하기 위한 주요 기준입니다:

1. 데이터 규모

   - 소규모 데이터(수백만 벡터 이하): Chroma, Faiss
   - 중규모 데이터(수천만~수억 벡터): Qdrant, Weaviate
   - 대규모 데이터(수십억 벡터 이상): Milvus, Pinecone

2. 배포 환경

   - 로컬/개발 환경: Chroma, Faiss
   - 자체 호스팅 필요: Milvus, Qdrant, Weaviate
   - 관리형 서비스 선호: Pinecone, Chroma Cloud

3. 기술적 복잡성 및 관리 리소스

   - 간단한 설정 선호: Chroma, Pinecone
   - 세밀한 제어 필요: Faiss, Milvus

4. 특수 기능 요구사항

   - 메타데이터 필터링 중요: Qdrant, Weaviate, Pinecone
   - 다중 모달 데이터(이미지+텍스트 등): Weaviate
   - GraphQL 인터페이스 필요: Weaviate
   - 순수 검색 성능 최적화: Faiss

5. 비용 고려사항

   - 예산 제한적: Chroma, Faiss(오픈소스)
   - 운영 비용 최소화: Pinecone(관리형 서비스)

6. 통합 용이성
   - LangChain과 통합: Chroma가 가장 원활함
   - REST API 필요: Qdrant, Weaviate, Pinecone

## 상황별 추천 벡터 DB

1. 프로토타입/소규모 프로젝트

   - Chroma: 빠른 설정, 간단한 API, 로컬 개발에 이상적

2. 연구/실험 환경

   - Faiss: 다양한 인덱싱 방법, 최고의 검색 성능, 커스터마이징 가능

3. 중소규모 프로덕션 환경

   - Qdrant: 강력한 필터링, 좋은 성능, 자체 호스팅 가능
   - Weaviate: 스키마 기반 접근, 다중 모달 데이터 처리 필요 시

4. 엔터프라이즈급 대규모 환경
   - Milvus: 대규모 분산 환경, 고성능 필요 시
   - Pinecone: 인프라 관리 부담 없이 대규모 확장 필요 시

## Chroma와 Faiss 비교 정정

### Chroma

- Chroma는 단순한 로컬 DB가 아니라 클라우드 배포도 지원합니다.
- 최근 버전에서는 분산 환경 지원이 개선되었습니다.
- 로컬 환경에서 쉽게 시작할 수 있지만, 프로덕션 환경을 위한 클라우드 배포 옵션도 제공합니다.
- 메모리 내 저장소뿐만 아니라 영구 저장소 옵션도 있습니다.

### Faiss

- Faiss는 C++로 작성되었지만 Python 인터페이스가 잘 구현되어 있어 사용이 용이합니다.
- 다만 영속성(persistence) 기능이 내장되어 있지 않아 별도의 저장 메커니즘이 필요합니다.
- 검색 성능 최적화에 중점을 둔 라이브러리로, 다양한 인덱싱 방법을 제공합니다.
